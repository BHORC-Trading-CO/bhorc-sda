# Чеклист ручного тестування — Privacy hardening (PR #2)

> **Зміна політики (2026-07-13):** проксі тепер **опціональний**. Fail-closed
> guard'и знято: акаунт без проксі логіниться, оновлює баланси/підтвердження і
> запускає браузер **напряму з реального IP** (усвідомлений вибір користувача).
> Пункти A1, A4, C1 (блокування) і C4 (аудит-лог `[privacy]`) **більше не
> актуальні**. Актуальним лишається інваріант: якщо проксі **прив'язаний** —
> весь трафік має йти тільки через нього (A2, A3, B, C2, D).

Перевірка фіксів витоку реального IP / деанонімізації (HIGH + MEDIUM + LOW).
Автотестів у проєкті немає, тож це єдиний спосіб довести коректність перед мерджем.

## 0. Підготовка середовища

Збирайте **BHORC SDA** через `npm run make`, потім виконайте `npm run verify:package`.
На macOS застосунок лежить у `out/BHORC SDA-darwin-<arch>/BHORC SDA.app`,
його код — у `Contents/Resources/app`. На Windows/Linux код лежить у
`out/BHORC SDA-<platform>-<arch>/resources/app` (`win32` або `linux`).
Назва каталогу даних лишається `trademanager-open-source` для сумісності;
`electron/dataDir.ts` закріплює його до завантаження сховищ.

**Інструменти:**
- **Wireshark** (Windows) — головний детектор витоку.
- Контрольований HTTP-проксі з логами (напр. **mitmproxy**/Burp або будь-який проксі, чий лог видно) — щоб бачити, що трафік реально йде через нього.
- DevTools браузера (F12) — для фінгерпринту.

**Золотий фільтр витоку (Wireshark).** Ідея: *кожне* вихідне TCP-з'єднання має йти **тільки** на IP проксі (або LAN/loopback). Будь-який SYN на публічний IP, що не є проксі — підозра на витік:

```
tcp.flags.syn==1 && tcp.flags.ack==0
&& !(ip.dst==<PROXY_IP>)
&& !(ip.dst==192.168.0.0/16) && !(ip.dst==10.0.0.0/8) && !(ip.dst==127.0.0.0/8)
```

**DNS-leak фільтр** (Steam-домени не мають резолвитись локально, якщо проксі робить remote DNS):

```
dns.qry.name contains "steam" || dns.qry.name contains "akamai" || dns.qry.name contains "valve"
```

Запускати захоплення **до** старту дії, зупиняти після.

## A. HIGH — fail-closed мережа

### A1. Баланси/підтвердження без проксі блокуються (HIGH-1)
- [ ] **Передумова:** акаунт **без** прив'язаного проксі.
- [ ] У таблиці увімкнути колонку балансу (тригерить `getChangableSecondary`) / відкрити вікно підтверджень (`getConfirmations`).
- [ ] **Очікувано:** операція **не виконується**, UI показує помилку «не привязан прокси…».
- [ ] У логах (DevTools main / консоль Electron) є запис `[privacy] аккаунт #N … заблокировано — нет прокси`.
- [ ] У Wireshark по золотому фільтру — **0** SYN на сторонні IP під час дії.

### A2. Баланси/підтвердження з проксі йдуть ТІЛЬКИ через проксі
- [ ] **Передумова:** той самий акаунт, прив'язати контрольований проксі.
- [ ] Повторити отримання балансу/підтверджень.
- [ ] **Очікувано:** дані вантажаться; у логах **проксі** видно запити до `steamcommunity.com`; у Wireshark усі SYN — лише на IP проксі.

### A3. Аватар при першому створенні профілю (HIGH-2)
- [ ] **Передумова:** видалити теку профілю `<userData>/browser_profiles/<id>` (userData Electron, напр. `%APPDATA%/<app>`; щоб спрацював `createProfile`), акаунт з проксі та непорожнім `avatarUrl`.
- [ ] Запустити браузер.
- [ ] **Очікувано:** аватар завантажився; у Wireshark запит до CDN Steam (`*.steamstatic.com`/akamai) НЕ йде напряму — лише через проксі. **0** прямих SYN.
- [ ] *(Defense-in-depth)* Зверніть увагу: запуск браузера без проксі тепер блокується слухачем ще до `createProfile` (див. A4), тож guard аватара — додатковий рівень; прямо через UI його не дотягнутись, це нормально.

### A4. Старт браузера без проксі блокується
- [ ] **Передумова:** акаунт без проксі.
- [ ] Натиснути «запустити браузер».
- [ ] **Очікувано:** браузер не стартує, UI показує помилку про відсутній проксі; **0** прямих SYN.

### A5. RequestPromise default-deny (HIGH-3)
- [ ] Тест проксі (`Proxy.test` / кнопка тесту) з валідним проксі — **працює** (проксі завжди передається).
- [ ] *(За бажанням, код-рівень)* переконатися, що `new RequestPromise(undefined)` кидає помилку — це латентний guard, через UI не тригериться.

## B. MEDIUM — фінгерпринт + фоновий трафік

### B1. Фінгерпринт головної сторінки відповідає гео проксі (MEDIUM-1)
- [ ] Запустити браузер акаунта з проксі відомої країни.
- [ ] У DevTools-консолі виконати:

```js
Intl.DateTimeFormat().resolvedOptions().timeZone   // має відповідати гео проксі
navigator.hardwareConcurrency                       // одне з 4/8/12/16
navigator.deviceMemory                              // 8 або 16
navigator.language                                  // локаль під гео проксі
```

- [ ] **Очікувано:** TZ і locale відповідають країні проксі (не системним).

### B2. Фінгерпринт попапа збігається з головною сторінкою
- [ ] У тій самій сесії відкрити попап/нову вкладку: у консолі `window.open('about:blank')` або клік по посиланню, що відкриває нову вкладку.
- [ ] У DevTools нової вкладки повторити 4 перевірки з B1.
- [ ] **Очікувано:** значення **ті самі**, що на головній (раніше на попапах була системна TZ/локаль).

### B3. Per-account стабільність і відмінність
- [ ] Запам'ятати `hardwareConcurrency`/`deviceMemory` акаунта A.
- [ ] Закрити браузер, перезапустити застосунок, знову відкрити акаунт A → **ті самі** значення (стабільні між запусками).
- [ ] Відкрити інший акаунт B → значення, як правило, **відрізняються** від A.

### B4. focus() не ходить на сторонній домен (MEDIUM-2)
- [ ] Захоплення увімкнено; викликати focus браузера (кнопка фокусу/відповідна дія).
- [ ] **Очікувано:** нова вкладка = `about:blank`; **жодного** запиту на сторонній домен (перевірити у Wireshark/DNS-фільтрі та візуально в адресному рядку).

### B5. Менше фонового трафіку Chromium (MEDIUM-3)
- [ ] Під час роботи браузера дивитись захоплення на сторонні Google/оновлення домени: `gvt1.com`, `clients*.google.com`, `safebrowsing`, `update`.
- [ ] **Очікувано:** цих звернень помітно менше/немає (best-effort; усе одно має йти через проксі, якщо й виникає). **0** прямих SYN повз проксі.

## C. LOW — стан проксі + аудит

### C1. Видалення прив'язаного проксі (LOW-1)
- [ ] **Передумова:** акаунт із прив'язаним проксі P.
- [ ] Видалити проксі P у застосунку.
- [ ] **Очікувано:** акаунт одразу показується **без проксі** (UI оновився); спроба балансів/підтверджень → блокується (як A1); у логах `[privacy] … заблокировано`.
- [ ] Раніший баг: акаунт «думав», що проксі ще є — переконатися, що цього **немає**.

### C2. Зняття/зміна проксі не лишає старого з'єднання
- [ ] Прив'язати проксі P1, відкрити баланс (працює) → зняти P1 → прив'язати P2.
- [ ] **Очікувано:** запити йдуть через **P2** (перевірити в логах P2), не через P1.

### C3. Створення акаунта по maFile з невалідною/відсутньою сесією (LOW-2)
- [ ] Створити/імпортувати акаунт по maFile, де збережена сесія прострочена (щоб спрацював шлях `createSession` → рекурсивний ретрай), **з** проксі.
- [ ] **Очікувано:** флоу **доходить до кінця** (логін → дані), а не падає з «прокси обязателен» після створення сесії.

### C4. Аудит-лог (LOW-4)
- [ ] Будь-яка заблокована дія з A1/C1 лишає у консолі запис `[privacy] аккаунт #N (<id>): "<дія>" заблокировано — нет прокси`.

## D. Регрес (нічого не зламали)

- [ ] **D1.** Нормальний логін/оновлення сесії акаунта з проксі — працює.
- [ ] **D2.** Підтвердження/скасування угод з проксі — працює, з'являється у логах проксі.
- [ ] **D3.** Steam-кукі підставляються, `steamcommunity.com/my/` відкривається залогіненим.
- [ ] **D4.** Аватар у профілі відображається.
- [ ] **D5.** Створення нового Guard-акаунта з проксі — повний флоу проходить.
- [ ] **D6.** Перемикання акаунтів / повторні відкриття браузера — без зависань і витоку SYN.

---

## Критерій приймання

PR можна мерджити, якщо:

- у всіх сценаріях **без проксі** золотий фільтр Wireshark показав **0** прямих вихідних SYN на сторонні IP;
- усі дії **з проксі** видно в логах саме того проксі;
- фінгерпринт головної сторінки = фінгерпринту попапа й відповідає гео проксі;
- регрес D1–D6 зелений.

## Поза обсягом PR (відомі обмеження)

- **Агресивний canvas/WebGL/fonts noise** — не реалізовано; `puppeteer-extra-plugin-stealth` уже нормалізує WebGL, власний шум ризикує конфліктом і детектом Steam. Потребує окремого протестованого fingerprint-механізму.
- **Вимикач `ipwho.is`** (geo-lookup) — не реалізовано; запит і так іде через проксі (реальний IP не тече), вимикач потребує налаштувань/UI.
